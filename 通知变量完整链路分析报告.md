## 1. 核心架构概述

通知系统采用分层设计，主要分为以下几个层次：

```
┌───────────────────────────────────────────────────────────────────┐
│                        触发层 (Trigger Layer)                      │
│  ┌─────────────────────┐    ┌─────────────────────────────────┐  │
│  │  生产检测触发        │    │  UI 手动测试触发                │  │
│  │  (worker.py)        │    │  (blueprint/ui/notification.py) │  │
│  └─────────────────────┘    └─────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────┘
                              ↓
┌───────────────────────────────────────────────────────────────────┐
│                    服务层 (Service Layer)                          │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │  NotificationService                                         │ │
│  │  - send_content_changed_notification()                       │ │
│  │  - queue_notification_for_watch()                            │ │
│  └─────────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────┘
                              ↓
┌───────────────────────────────────────────────────────────────────┐
│                    渲染层 (Render Layer)                           │
│  ┌──────────────────┐  ┌─────────────────────────────────────┐  │
│  │ Notification-    │  │  Jinja2 安全渲染                     │  │
│  │ ContextData      │  │  (jinja2_custom/safe_jinja.py)       │  │
│  └──────────────────┘  └─────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────┘
                              ↓
┌───────────────────────────────────────────────────────────────────┐
│                    分发层 (Distribution Layer)                     │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │  process_notification() (notification/handler.py)           │ │
│  │  - apply_service_tweaks()                                    │ │
│  │  - Apprise 分发                                              │ │
│  └─────────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────┘
```

## 2. 生产触发路径完整调用链

### 2.1 入口条件

**触发条件**：
- 监控任务 (`Watch`) 达到执行时间
- 内容抓取完成且检测到变化 (`changed_detected = True`)
- 历史快照数 ≥ 2（至少有两个版本才能比较）
- 通知未被静音 (`notification_muted = False`)

**入口函数**：`async_update_worker()` (`changedetectionio/worker.py`)

---

### 2.2 完整调用链

#### 阶段 1: 内容抓取与变化检测

```python

# 文件: changedetectionio/notification_service.py - NotificationService

def send_content_changed_notification(self, watch_uuid):
    """
    发送内容变化检测通知
    """
    # 1. 创建空的通知上下文对象
    n_object = NotificationContextData()
    
    # 2. 获取监控对象
    watch = self.datastore.data['watching'].get(watch_uuid)
    
    # 3. 级联获取通知配置（监控 → 标签 → 全局）
    n_object['notification_urls'] = _check_cascading_vars(...)
    n_object['notification_title'] = _check_cascading_vars(...)
    n_object['notification_body'] = _check_cascading_vars(...)
    n_object['notification_format'] = _check_cascading_vars(...)
    
    # 4. 附加 LLM 结果
    n_object['_llm_result'] = watch.get('_llm_result')
    n_object['_llm_intent'] = watch.get('_llm_intent', '')
    n_object['_llm_change_summary'] = watch.get('_llm_change_summary', '')
    
    # 5. 将通知放入队列
    count = watch.get('notification_alert_count', 0) + 1
    self.datastore.update_watch(uuid=watch_uuid, 
                                update_obj={'notification_alert_count': count})
    self.queue_notification_for_watch(n_object=n_object, watch=watch)
```

```python
# 文件: changedetectionio/notification_service.py - queue_notification_for_watch()

def queue_notification_for_watch(self, n_object, watch, date_index_from=-2, date_index_to=-1):
    # 1. 获取历史快照日期
    watch_history = watch.history
    dates = list(watch_history.keys())
    
    # 2. 获取触发文本（如果有）
    if len(dates):
        snapshot_contents = watch.get_history_snapshot(timestamp=dates[-1])
        triggered_text = html_tools.get_triggered_text(...)
    
    # 3. 获取历史快照内容
    if len(dates) > 1:
        # 真实历史数据
        prev_snapshot = watch.get_history_snapshot(timestamp=dates[date_index_from])
        current_snapshot = watch.get_history_snapshot(timestamp=dates[date_index_to])
    else:
        # 无历史数据时的默认示例
        prev_snapshot = "Example text: example test\nExample text: change detection is cool..."
        current_snapshot = "Example text: example test\nExample text: change detection is fantastic..."
    
    # 4. 设置基础通知变量
    n_object.update(set_basic_notification_vars(
        current_snapshot=current_snapshot,
        prev_snapshot=prev_snapshot,
        watch=watch,
        triggered_text=triggered_text,
        timestamp_changed=dates[date_index_to]
    ))
    
    # 5. 放入通知队列
    if self.notification_q:
        logger.debug("Queued notification for sending")
        self.notification_q.put(n_object)  # 通知在此进入队列等待消费
```

## 4. 消息下发阶段正确执行顺序

### 4.1 核心入口函数

**函数**：`process_notification(n_object, datastore)`  
**文件**：`changedetectionio/notification/handler.py`

---

### 4.2 正确执行顺序（19 个步骤）

```
┌─────────────────────────────────────────────────────────────────┐
│                     阶段 A: 初始化准备                            │
└─────────────────────────────────────────────────────────────────┘

步骤 1: 类型检查
  → if not isinstance(n_object, NotificationContextData): raise TypeError

步骤 2: 创建通知参数字典
  → notification_parameters = create_notification_parameters(n_object, datastore)
    └─ 解析 URL, title, body, format 的级联配置
    └─ 注入 watch_uuid, watch_url, watch_title, watch_tag 等
    └─ 注入 diff_url, preview_url, edit_url 等链接
    └─ 调用 watch.extra_notification_token_values() 添加额外变量

步骤 3: 确定输出格式
  → requested_output_format = n_object.get('notification_format', default)
  → 如果是 "System default", 查询全局配置
  → requested_output_format = notification_format_align_with_apprise(...)
     └─ 对齐到 Apprise 支持的格式 (HTML/TEXT/MARKDOWN)

┌─────────────────────────────────────────────────────────────────┐
│                   阶段 B: 差异渲染与智能处理                       │
└─────────────────────────────────────────────────────────────────┘

步骤 4: 按需渲染差异变量（性能优化）
  → scan_text = notification_body + notification_title
  → diff_vars = add_rendered_diff_to_notification_vars(
        notification_scan_text=scan_text,
        current_snapshot=n_object.get('current_snapshot'),
        prev_snapshot=n_object.get('prev_snapshot'),
        word_diff=True/False
    )
  → n_object.update(diff_vars)
    └─ 只渲染模板中实际使用的 {{ diff_* }} 变量，避免不必要计算
    └─ 支持 diff, diff_clean, diff_added, diff_removed, diff_full 等变体
    └─ 支持 diff_changed_from, diff_changed_to 提取变量

步骤 5: 保存原始差异到 raw_diff
  → n_object['raw_diff'] = n_object.get('diff', '')
    └─ raw_diff 始终保存真实差异，不受 AI 摘要影响

步骤 6: AI 摘要覆盖（可选）
  → _llm_change_summary = (n_object.get('_llm_change_summary') or '').strip()
  → _override_diff = datastore.data['settings']['application'].get('llm_override_diff_with_summary', True)
  → if _llm_change_summary and _override_diff:
        n_object['diff'] = _llm_change_summary

步骤 7: 懒加载 LLM 相关变量（如果模板使用了）
  → if 'llm_summary' in scan_text or 'llm_intent' in scan_text or 'raw_diff' in scan_text:
        n_object['llm_summary'] = _llm_change_summary or ...
        n_object['llm_intent'] = n_object.get('_llm_intent', '')

步骤 8: HTML 安全转义（XSS 防护）
  → if 'html' in requested_output_format:
        from markupsafe import escape as html_escape
        _page_content_keys = {'raw_diff', 'current_snapshot', 'prev_snapshot', 'triggered_text'}
        for key in [k for k in notification_parameters if k.startswith('diff') or k in _page_content_keys]:
            if notification_parameters.get(key):
                notification_parameters[key] = str(html_escape(str(notification_parameters[key])))
    └─ 防止被监控页面注入恶意 HTML/JavaScript

┌─────────────────────────────────────────────────────────────────┐
│                   阶段 C: 按渠道逐个处理                           │
└─────────────────────────────────────────────────────────────────┘

步骤 9: 初始化 Apprise 实例
  → apobj = apprise.Apprise(debug=True, asset=apprise_asset)
  → 注册自定义 Discord 插件（支持彩色 Embed）

步骤 10: 遍历每个通知 URL (for url in n_object['notification_urls'])

    子步骤 10a: Jinja2 渲染通知正文
      → n_body = jinja_render(template_str=n_object.get('notification_body', ''), 
                              **notification_parameters)

    子步骤 10b: Jinja2 渲染通知标题
      → n_title = jinja_render(template_str=n_object.get('notification_title', ''), 
                               **notification_parameters)

    子步骤 10c: 自动链接转换（可选）
      → if n_object.get('markup_text_links_to_html_links'):
            n_body = markup_text_links_to_html(body=n_body)
          └─ 将纯文本 URL 转换为 HTML <a> 链接

    子步骤 10d: Jinja2 渲染通知 URL 本身（支持 Token）
      → url = url.strip()
      → url = jinja_render(template_str=url, **notification_parameters)
        └─ 支持在 Apprise URL 中使用变量，如 {{watch_uuid}} 等

    子步骤 10e: HTML 格式空白保留
      → if 'html' in requested_output_format:
            n_body = n_body.replace('  ', '&nbsp;&nbsp;')

    子步骤 10f: 应用渠道特定格式调整
      → (url, n_body, n_title) = apply_service_tweaks(
            url=url, 
            n_body=n_body, 
            n_title=n_title, 
            requested_output_format=requested_output_format_original
        )
        └─ Telegram: 限制长度, <s> 删除标记, <b> 加粗
        └─ Discord: 转换为 Embed 格式, 颜色标记差异
        └─ HTML: <span> 颜色标记, 换行转 <br>
        └─ Markdown: ~~ 删除, ** 新增
        └─ Text: (removed) / (added) 文字标记

    子步骤 10g: 确定 Apprise 输入格式
      → if not 'format=' in url:
            if 'html' in requested_output_format:
                url += '&format=html'
                apprise_input_format = NotifyFormat.HTML.value
            elif 'text' in requested_output_format:
                url += '&format=text'
                apprise_input_format = NotifyFormat.TEXT.value
            elif requested_output_format == NotifyFormat.MARKDOWN.value:
                n_body = markdown_to_html(n_body)  # 自己转换
                url += '&format=html'
                apprise_input_format = NotifyFormat.HTML.value
        └─ 关键: 禁用 Apprise 自动转换，自己控制格式

    子步骤 10h: 邮件 HTML 美化
      → if url.startswith('mail') and 'html' in requested_output_format:
            if not '<pre' in n_body and not '<body' in n_body:
                n_body = as_monospaced_html_email(content=n_body, title=n_title)

    子步骤 10i: 添加到 Apprise
      → if not url.startswith('null://'):
            apobj.add(url)

    子步骤 10j: 记录发送对象（用于调试）
      → sent_objs.append({'title': n_title, 'body': n_body, 'url': url, ...})

┌─────────────────────────────────────────────────────────────────┐
│                   阶段 D: 实际发送与日志                           │
└─────────────────────────────────────────────────────────────────┘

步骤 11: 执行实际通知发送
  → if not url.startswith('null://'):
        apobj.notify(
            title=n_title,
            body=n_body,
            body_format=apprise_input_format,
            attach=n_object.get('screenshot', None)
        )
    └─ body_format: 告诉 Apprise 输入内容的格式，避免自动转换
    └─ attach: 附加截图（如果启用 notification_screenshot）

步骤 12: 日志捕获与错误处理
  → with apprise.LogCapture(level=apprise.logging.DEBUG) as logs:
        ...
    log_value = logs.getvalue()
    if log_value and ('WARNING' in log_value or 'ERROR' in log_value):
        logger.critical(log_value)
        raise Exception(log_value)

步骤 13: 返回发送结果
  → return sent_objs
```

## 5. 抓取数据到渲染上下文转换流程

### 5.1 数据流概览

```
抓取层 (Fetcher)
    │
    ├─ fetcher.content (原始 HTML/文本)
    ├─ fetcher.headers (响应头)
    ├─ fetcher.status_code (HTTP 状态)
    └─ fetcher.screenshot (截图二进制，可选)
        ↓
变化检测层 (Processor)
    │
    ├─ 执行过滤器 include_filters (CSS/XPath/JSONPath)
    ├─ 提取文本内容 (inscriptis/html_tools)
    ├─ 计算内容 MD5 checksum
    ├─ 与前一版本比较 → changed_detected
    └─ 提取触发文本 (triggered_text)
        ↓
历史存储层
    │
    ├─ 保存到 history_blob 文件
    ├─ 更新 watch.history 索引
    └─ 保存截图文件 (如果需要)
        ↓
通知上下文构建 (NotificationService)
    │
    ├─ 从历史读取: prev_snapshot = watch.get_history_snapshot(dates[-2])
    ├─ 从历史读取: current_snapshot = watch.get_history_snapshot(dates[-1])
    ├─ set_basic_notification_vars()
    │   ├─ current_snapshot, prev_snapshot
    │   ├─ screenshot
    │   ├─ change_datetime (FormattableTimestamp)
    │   ├─ triggered_text
    │   ├─ uuid, watch_url, watch_uuid, watch_mime_type
    │   └─ watch.extra_notification_token_values()
    └─ 创建 NotificationContextData 对象
        ↓
差异渲染 (add_rendered_diff_to_notification_vars)
    │
    ├─ 扫描模板使用了哪些 {{ diff_* }} 变量
    ├─ 按需创建 FormattableDiff 对象
    │   ├─ diff, diff_clean
    │   ├─ diff_added, diff_removed
    │   ├─ diff_full, diff_patch
    │   └─ diff_changed_from, diff_changed_to (FormattableExtract)
    └─ 注入到 n_object
        ↓
模板渲染 (jinja_render)
    │
    ├─ notification_body 模板渲染
    ├─ notification_title 模板渲染
    └─ notification_url 模板渲染
        ↓
渠道适配 (apply_service_tweaks)
    │
    ├─ 差异占位符替换为渠道特定格式
    │   ├─ HTML → <span style="color:red">
    │   ├─ Discord → ~~ 删除 ** 新增
    │   ├─ Telegram → <s> 删除 <b> 新增
    │   └─ Text → (removed) / (added)
    ├─ 长度限制截断 (Telegram/Discord)
    └─ 换行符转换 (\n → <br>)
        ↓
Apprise 分发
    ↓
实际通知渠道 (Email/Slack/Telegram/Discord/Webhook 等)
```

### 5.2 关键数据转换点详解

#### 转换点 1: 原始内容 → 处理后快照

```python
# 文件: changedetectionio/processors/text_json_diff/__init__.py

def run_changedetection(self, watch, force_reprocess=False):
    # 1. 获取抓取的原始内容
    raw_content = self.fetcher.content
    
    # 2. 应用包含/排除过滤器
    filtered_content = apply_filters(raw_content, watch.get('include_filters'), ...)
    
    # 3. 应用文本替换规则
    replaced_content = apply_substitutions(filtered_content, watch.get('subtractive_selectors'))
    
    # 4. 空白规范化
    normalized_content = normalize_whitespace(replaced_content)
    
    # 5. 计算 checksum
    current_md5 = hashlib.md5(normalized_content.encode('utf-8')).hexdigest()
    
    # 6. 与前一版本比较
    if current_md5 != watch.get('previous_md5'):
        changed_detected = True
    
    return changed_detected, update_obj, normalized_content
```

#### 转换点 2: 双快照 → 可格式化差异对象

```python
# 文件: changedetectionio/notification_service.py

class FormattableDiff(str):
    def __new__(cls, prev_snapshot, current_snapshot, **base_kwargs):
        # 1. 调用 diff 引擎渲染差异
        rendered = diff_module.render_diff(prev_snapshot, current_snapshot, **base_kwargs)
        # 2. 创建 str 子类实例
        instance = super().__new__(cls, rendered)
        # 3. 保存原始数据和配置，供后续调用
        instance._prev = prev_snapshot
        instance._current = current_snapshot
        instance._base_kwargs = base_kwargs
        return instance
    
    def __call__(self, lines=None, added_only=False, removed_only=False, 
                 context=0, word_diff=None, ...):
        """支持在 Jinja2 模板中动态调用: {{ diff(lines=5) }}"""
        kwargs = dict(self._base_kwargs)
        # 应用动态参数
        if added_only: kwargs['include_removed'] = False
        if removed_only: kwargs['include_added'] = False
        if context: kwargs['context_lines'] = int(context)
        if word_diff is not None: kwargs['word_diff'] = bool(word_diff)
        # 重新渲染
        result = diff_module.render_diff(self._prev, self._current, **kwargs)
        # 截断行数
        if lines is not None:
            result = '\n'.join(result.splitlines()[:int(lines)])
        return result
```

#### 转换点 3: 差异占位符 → 渠道特定格式

```python
# 文件: changedetectionio/notification/handler.py - replace_placemarkers_in_text()

# diff.render_diff() 输出中使用的占位符标记
REMOVED_PLACEMARKER_OPEN = '\x02r\x03'    # STX + 'r' + ETX
REMOVED_PLACEMARKER_CLOSED = '\x02/R\x03'
ADDED_PLACEMARKER_OPEN = '\x02A\x03'
ADDED_PLACEMARKER_CLOSED = '\x02/a\x03'
CHANGED_PLACEMARKER_OPEN = '\x02c\x03'
CHANGED_PLACEMARKER_CLOSED = '\x02/C\x03'

def replace_placemarkers_in_text(text, url, requested_output_format):
    """根据通知渠道替换差异占位符"""
    
    if url.startswith('tgram://'):
        # Telegram HTML 格式
        text = text.replace(REMOVED_PLACEMARKER_OPEN, '<s>')
        text = text.replace(REMOVED_PLACEMARKER_CLOSED, '</s>')
        text = text.replace(ADDED_PLACEMARKER_OPEN, '<b>')
        text = text.replace(ADDED_PLACEMARKER_CLOSED, '</b>')
        
    elif 'discord://' in url and requested_output_format == 'html':
        # Discord Markdown 格式
        text = apply_discord_markdown_to_body(text)
        
    elif requested_output_format == 'htmlcolor':
        # 带颜色的 HTML (邮件等)
        text = text.replace(REMOVED_PLACEMARKER_OPEN, 
                           f'<span style="{HTML_REMOVED_STYLE}">')
        text = text.replace(REMOVED_PLACEMARKER_CLOSED, '</span>')
        text = text.replace(ADDED_PLACEMARKER_OPEN, 
                           f'<span style="{HTML_ADDED_STYLE}">')
        text = text.replace(ADDED_PLACEMARKER_CLOSED, '</span>')
        
    elif requested_output_format == 'markdown':
        # Markdown 格式
        text = apply_standard_markdown_to_body(n_body=text)
        
    else:
        # 纯文本格式 - 使用文字标记
        text = text.replace(REMOVED_PLACEMARKER_OPEN, '(removed) ')
        text = text.replace(REMOVED_PLACEMARKER_CLOSED, '')
        text = text.replace(ADDED_PLACEMARKER_OPEN, '(added) ')
        text = text.replace(ADDED_PLACEMARKER_CLOSED, '')
```

## 6. 两条路径的入口条件和差异对比

### 6.1 入口条件对比

| 维度 | 生产触发路径 | 测试发送路径 |
|------|-------------|-------------|
| **触发源** | 后台 Worker 定时检测 | 用户在 UI 点击按钮 |
| **入口函数** | `async_update_worker()` | `ajax_callback_send_notification_test()` |
| **HTTP 请求** | 无（后台进程） | `POST /notification/send-test/<uuid>` |
| **前置条件** | 1. 达到检测时间<br>2. 成功抓取内容<br>3. 检测到内容变化<br>4. 历史快照数 ≥ 2<br>5. 通知未静音 | 1. 已配置 notification_urls<br>2. 有效的监控 UUID<br>3. Apprise URL 格式正确 |
| **变化检测** | 必须执行并检测到变化 | 跳过检测，直接构建测试数据 |
| **LLM 处理** | 支持 AI 意图过滤和摘要生成 | 通常不执行（除非历史中已有 LLM 结果）|

### 6.2 执行流程差异

| 步骤 | 生产触发路径 | 测试发送路径 |
|------|-------------|-------------|
| **1. 内容抓取** | ✓ 真实抓取目标网站 | ✗ 跳过（使用历史快照或示例文本） |
| **2. 变化检测** | ✓ 真实 diff 计算 | ✗ 跳过 |
| **3. LLM 处理** | ✓ 支持意图过滤/摘要 | ✗ 通常跳过（除非已有历史结果） |
| **4. 快照来源** | 刚抓取的最新内容 + 上一版本历史 | 最近两个历史快照 或 示例文本 |
| **5. 级联配置** | ✓ 监控 → 标签 → 全局 | ✓ 表单值 → 全局 → 默认值 |
| **6. 通知队列** | ✓ 先入队，异步消费 | ✗ 直接同步调用 process_notification() |
| **7. 异步模式** | ✓ 默认异步 | ✗ 强制同步 (`as_async=False`) |
| **8. 告警计数** | ✓ `notification_alert_count += 1` | ✗ 不增加 |
| **9. 通知 URL 验证** | 运行时才验证 | ✓ 发送前先验证 URL 有效性 |
| **10. 触发文本** | ✓ 计算触发匹配文本 | ✗ 空字符串 |

### 6.3 关键差异详解

#### 差异 1: 队列机制

**生产路径**：
```python

    logger.debug("Queued notification for sending")
```

**设计意图**：
- 生产路径使用队列解耦，避免通知发送阻塞后续检测任务
- 测试路径同步发送，用户能立即看到成功/失败结果

**生产路径**：
